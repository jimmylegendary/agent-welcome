# Jimmy Game Planning

Translate the game goal into a playable loop and a testable first slice.

- Separate player-facing information from hidden world state, authored canon, and implementation data.
- State the player verb, challenge, feedback, reward, and repeat point for each core loop.
- Define units, bounds, inputs, state changes, and failure cases for mechanics before proposing balancing numbers.
- Label untested tuning as a hypothesis. A design simulation or AI review is not a playtest.
- For an existing engine or project, preserve its data format and stable IDs; check project-specific instructions before changing serialized content.
- End with a small acceptance checklist a developer or tester can observe.
